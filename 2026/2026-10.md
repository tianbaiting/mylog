- **2026-10-22 15:35** spirit meeting left right problem

Kaneko 在分 析 note 第 19–20 页、§6.3 “TPC PID flattening”里，明确指出不同 pitch、yaw 角度 下，dE/dx–刚度图中的粒子带会偏移。因此，同一 种粒子、相同刚度，朝不同方向飞出，测到的 dE/ dx 分布也可能不同。

论文 §4.7.2 写 到：磁场让大量带电粒子弯向 beam-right，也就是 φ≈±180° 一侧；相反的 φ≈0° 一侧轨迹密度较低，预期有更稳定的重建效率和更好的粒子分离。因此 他最终选择 −30°≤φ≤20° 的范围进行氢同位素分析。

 他选择 −30°≤φ≤20°，即 φ≈0°、与 beam-right 相对
的一侧，主要考虑：

第一，这个方向有较大的有效探测体积，轨迹有较好
的测量条件。

第二，避开束流轨迹上方和下方受到强束流电离影响
的区域。论文指出，这种影响会扰动 hit cluster
的位置和电荷，从而影响轨迹重建和 PID。

第三，磁场让大量带电粒子弯向 beam-
right（φ≈±180°），使那一侧更拥挤。φ≈0° 一侧轨
迹密度较低，作者因此预期其重建效率更稳定、粒子
分离能力更好。


- **2026-10-27 14:14**  Aki 这套历史代码的做法

  模拟端：
  生成已知粒子的动量和顶点 → Geant4 输运、产生能量沉积 → 漂移、扩散、pad 响应和电
  子学数字化 → 得到模拟 STRawEvent 波形。

  真实数据端：
  读取 GET 文件和 metadata → STDecoderTask 解码、校准 → 得到真实 STRawEvent 波形。

  然后在两条链的汇合处执行 STEmbedTask：
  按相同的 pad row、layer 和 time bucket，将模拟 ADC 加到真实 ADC 上。安装版源码中
  能直接看到 adc_real＋adc_MC；对已经饱和的真实 pad，还有限制叠加时间范围的处理。

  混合之后：
  重新运行 PSA → helix 找轨和聚类 → 饱和/PRF、空间电荷修正 → GENFIT → VA 重拟合 →
  识别注入粒子对应的重建结果。

  所以不需要提前单独保存一份“背景波形 ROOT 文件”。真实 GET 可以在同一次任务里解码
  成内存中的 STRawEvent，立即做 embedding。Aki 的宏就是接入解码器后再加入
  STEmbedTask。

  其他 SπRIT 分析确实这样做过

  Kaneko 等人的 2021 年 RIKEN 报告写得很明确：模拟单个质子通过 TPC
  的数字化信号，把它加入真实事件，再使用与真实粒子相同的找轨算法重建，以研究高多重
  数环境下的重建效率。报告明确提到真实信号相互干扰会造成合轨和断轨。原始报告
  (https://www.nishina.riken.jp/researcher/APR/APR054/pdf/16.pdf\)

  他们还考虑了动量分辨率导致的分箱迁移，对注入质子的运动学分布进行重加权，并迭代修
  正谱。因此，实际分析不只是简单数“最后多了几条轨迹”。同一报告
  (https://www.nishina.riken.jp/researcher/APR/APR054/pdf/16.pdf\)

  其他实验的原则也类似

  STAR 的 TPC embedding
  同样把模拟探测器响应加入真实事件，然后整体重建，并将重建轨迹与 MC 真值关联。STAR
  方法说明 (https://drupal.star.bnl.gov/STAR/files/Thesis_2_0.pdf)


确保模拟重建与真实数据使用了相同的：
1. 电子学信号处理与 cluster finding。
2. Track finding、track fitting 和 track selection。
3. Space charge、漂移速度、增益等 calibration。
4. PID 和 momentum reconstruction，包括粒子质量假设
